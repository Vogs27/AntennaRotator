# Rotator Firmware

This firmware is based on [SatNOGS Rotator Controller](https://gitlab.com/librespacefoundation/satnogs/satnogs-rotator-firmware), adapted for a SAMD21 board driving two stepper motors through TMC2209 drivers. It is still young: test it on the bench before trusting it on a mast.

## Instructions

In order to use this code, you need to install:
 * [AccelStepper library](http://www.airspayce.com/mikem/arduino/AccelStepper/index.html)
 * [TMCStepper library](https://github.com/teemuatlut/TMCStepper)
 * [Adafruit SleepyDog library](https://github.com/adafruit/Adafruit_SleepyDog) (watchdog)
 * Arduino IDE with the Arduino SAMD Boards core

#### Burn the bootloader

Only with SWD programming:

* Jlink like programmer
* Arduino Micro as DAP device

Connect the programmer to the SWD port on the board. Using Arduino IDE, select Arduino Zero (programming port), then burn bootloader. Wait while flashing the bootloader and disconnect the programmer.

#### Upload the code

Connect a USB cable to the controller board. Select Arduino Zero (native port) in Arduino IDE. Open the main firmware file (.ino) in Arduino IDE and press Upload. Wait while flashing the firmware. Disconnect USB cable.

## Testing with hamlib - rotctl or with Serial Monitor

Connect the PC with the controller via an RS485 to USB converter.

```
rotctl -m 204 -s 19200 -r /dev/ttyUSB1 -vvvvv
```

Replace /dev/ttyUSB1 with the device connected to the PC. Model 204 is Easycomm III (model 202, Easycomm II, also works but has no velocity commands).

You can also type Easycomm commands directly in a terminal, terminated by CR or LF.

## Use with Gpredict
Configure Gpredict and launch the hamlib daemon with:
```
rotctld -m 204 -r COM7 -s 19200 -T 127.0.0.1 -t 4533 -C timeout=500 -C retry=0 > pause
```
Replace COM7 with the device connected to the PC.

## Easycomm implementation

The implementation follows the Easycomm II/III specification shipped with Hamlib (`rotators/easycomm/easycomm.txt`) and the behaviour of the Hamlib easycomm backend.

Parsing rules:

* A line ends with CR or LF. Within a line, commands are separated by spaces, as the specification requires: `AZ10.0 EL20.0` and `SA SE` are two commands each. `;` is also a separator because Hamlib appends one after some commands (`GS\n;`).
* All replies generated by one line are joined with a space and sent as one line ending in `\n`. Hamlib >= 4.6 queries `AZ` and `EL` separately and gets `AZ123.4` and `EL45.6`; older Hamlib and other clients send `AZ EL` and get `AZ123.4 EL45.6`.
* Commands that only set something do not reply.
* Lines longer than 127 characters are discarded.

#### Commands

* AZ, Azimuth. `AZ` queries, `AZnnn.n` sets [deg]. Values outside the travel limits are clamped.
* EL, Elevation. `EL` queries, `ELnnn.n` sets [deg]. Values outside the travel limits are clamped.
* SA, Stop azimuth (decelerates)
* SE, Stop elevation (decelerates)
* ML / MR / MU / MD, Move left / right / up / down at 5 deg/s until SA/SE or the travel limit (Easycomm II)
* VL, Velocity Left (azimuth decreasing), number [mdeg/s]
* VR, Velocity Right (azimuth increasing), number [mdeg/s]
* VU, Velocity Up, number [mdeg/s]
* VD, Velocity Down, number [mdeg/s]
  * A velocity of 0 stops the axis. Motion stops at the travel limit. Hamlib sends `(speed - 1) * 100` mdeg/s for `rotctl M <dir> <speed 1-100>`.
* RESET, clear the latched errors and re-home (custom, used by `rotctl R`)
* PARK, move to the park position (custom, used by `rotctl K`)
* VE, Request Version
* GS, Get status register, bitmask
    * idle = 1
    * moving = 2 (velocity/move commands, homing)
    * pointing = 4 (slewing to an AZ/EL set point)
    * error = 8
    * warning = 16 (extension: a driver reports the over-temperature pre-warning)
* GE, Get error register, bitmask, latched until RESET
    * no error = 0
    * sensor error = 1 (reserved)
    * jam = 2 (reserved)
    * homing error = 4
    * motor/driver error = 8 (extension: short circuit, driver UART lost, driver reset, charge pump undervoltage)
    * over temperature = 16 (extension)
    * watchdog reset = 32 (extension)
* IPn, Read an input. Reply `IPn,value`. The index may follow a space (`IP 5`).
    * Driver temperature = 0, highest TMC2209 threshold exceeded: 0 (below 120), 120, 143, 150 or 157 degC
    * SW1 = 1
    * SW2 = 2
    * Position of AZ in deg = 3
    * Position of EL in deg = 4
    * Actual current scale of AZ driver, 0-31 = 5 (CS_ACTUAL, not a mechanical load measurement)
    * Actual current scale of EL driver, 0-31 = 6
    * Speed of AZ in deg/s = 7
    * Speed of EL in deg/s = 8
    * AZ driver DRV_STATUS flags, bits 0-11 = 9
    * EL driver DRV_STATUS flags, bits 0-11 = 10
    * AZ driver chopper mode, 1 = StealthChop, 0 = SpreadCycle = 11
    * EL driver chopper mode = 12
    * Digital level of AUX GPIO 0-7 = 20-27 (see AUX GPIO below)
* ANn, Read AUX GPIO 0-5 (A0-A5) as analogue input, raw ADC value. Reply `ANn,value`. Refused with `ALANn_is_output` if the pin was set as output with OP.
* OPn,v, Set AUX GPIO n (0-7) as output, low if v = 0, high otherwise (`OP6,1`)
* CRr, Read config. Reply `CRr,value`.
    * Max slew speed for AZ/EL commands, mdeg/s = 0
    * Overshoot = a, always `-` (not supported)
    * Jamming detection = b, always `-` (not supported)
    * Endpoints = c, always `1` (end-stops are used for homing)
    * Unstick = d, always `-` (not supported)
    * Azimuth park position = 7
    * Elevation park position = 8
    * Control mode (position = 0, velocity = 1), read only = 9
* CWr,v, Write config (registers 0, 7, 8). Park positions outside the travel limits are rejected.
* UP, DN, DM, UM, DR, UR, AO, LO, ST: accepted and ignored (radio and time commands).
* RB, reboot the controller (custom)
* RST, hang the firmware to test the watchdog (custom)

When an index is missing (Hamlib's `get_conf` sends `IP` and `AN` without one), the controller replies with an alarm, e.g. `ALIP_needs_index`.

## Safety features

#### Fault handling

Every error is latched. On a fault the step generator is stopped, the motors are disabled through MOTOR_EN and through the driver (TOFF = 0), and the position reference is marked as lost. `RESET` clears the errors, reconfigures the drivers and re-homes. `RESET` does not clear an over-temperature error while a driver still reports it.

Note: with the motors disabled the antenna is held only by the gearbox. If yours is not self-locking, wind can move it.

#### Watchdog

The watchdog (`WDT_TIMEOUT_MS`, 2 s) is fed from the main loop. Nothing in the loop blocks for long: RS485 transmission, homing and driver diagnostics are non-blocking or bounded to a few milliseconds.

On SAMD the watchdog resets the chip directly, there is no interrupt routine as on AVR. At boot the firmware reads the reset cause; after a watchdog reset it starts in error with `GE` = 32 and the motors off, waiting for `RESET`. The easycomm handler keeps running, so the host can read `GS`/`GE`. Set `WDT_LATCH_ERROR` to 0 to re-home automatically instead (the error bit is still reported).

During an MCU reset STEPPER_EN floats and R19 (10k to 3V3) pulls ENN high, so both drivers are disabled.

#### Over-temperature and driver protection

The firmware has no dedicated temperature sensor, so it uses the TMC2209 diagnostics read over UART (DRV_STATUS and GSTAT):

* `ot` (driver shut down by over-temperature) -> over temperature error
* `otpw` (120 degC pre-warning) -> over temperature error if `OTPW_IS_FAULT` is 1 (default), otherwise only the warning bit 16 in `GS`
* `s2ga`/`s2gb`/`s2vsa`/`s2vsb` (short to ground or supply), `GSTAT.reset` (the driver lost its configuration, e.g. motor supply brown-out), `GSTAT.drv_err`, `GSTAT.uv_cp`, or 3 consecutive failed UART reads -> motor/driver error

The thresholds of the temperature flags are set by the driver: check them in the TMC2209 datasheet.

The DIAG outputs of both drivers (PA19, PA17) are also read every loop iteration. A DIAG level held high for 1 ms stops the rotator immediately, even during fast slews when UART polling is deferred; a UART read then tells over-temperature from other faults. DIAG can also signal StallGuard events; the firmware sets TCOOLTHRS = 0 and SGTHRS = 0 so it does not.

A UART read blocks for a few milliseconds (TMCStepper waits for the reply), which would disturb the step timing at high speed. For this reason one driver is polled every 250 ms (`DIAG_PERIOD_MS`), and polling is deferred while an axis runs faster than `DIAG_MAX_STEP_RATE` (1000 steps/s, about 2 deg/s). Satellite tracking is slower than this, so polling continues during passes; during fast slews it resumes as soon as the slew ends. The driver protects itself during the slew. The TMC2209 UART runs at 115200 baud to keep reads short.

If the drivers are not powered at boot (motor supply off), the controller starts with `GE` = 8: power them and send `RESET`.

## Board configuration (RotatorMobo rev 1.0a)

The firmware assumes these solder jumpers:

* JP3/JP4 (A_AD0/A_AD1): both to GND, azimuth driver UART address 0
* JP5 (E_AD0) to 3V3, JP6 (E_AD1) to GND, elevation driver UART address 1
* JP1 (RS485_EN): to 3V3 to enable the level shifter for RS485. To GND to use the CN5 serial adapter on the same UART instead.

* JP7 (AMODE, azimuth) and JP8 (EMODE, elevation), SPREAD pins: select the chopper mode. GND = StealthChop (quiet), 3V3 = SpreadCycle. The firmware writes `en_spreadCycle = 0`, so the pin alone decides (a high SPREAD pin inverts that register bit). `IP11`/`IP12` report the mode each driver is actually running in.

The VREF pins of the TMC2209 are connected only to test points, so the firmware sets `I_scale_analog = 0` and the current is set by `MOTOR_CURRENT_MA` through the UART using the internal reference. TMCStepper's default is `I_scale_analog = 1`, which would scale the current by the floating VREF voltage.

The MS1/MS2 pins are used only as UART address: microstepping comes from the register (`mstep_reg_select = 1`, set by TMCStepper's `begin()`).

#### End-stops

CN10/CN11 expect a SPDT microswitch with the common on pin 2 and the throws on 3V3 (pin 1) and GND (pin 3), so the line is always driven. `DEFAULT_HOME_STATE` is the level when the switch is pressed. The firmware enables the internal pull towards the opposite level: it only matters when the cable is disconnected, and then the end-stop never triggers and homing ends in a homing error instead of a false home at the current position.

#### AUX GPIO

The AUX (CN9) and AUX2 (CN7) pins are connected only to the MCU and can be used as general purpose I/O. They are inputs (high impedance) after reset until set with `OP`.

```
n  Pin  Port  Connector         Use
0  A0   PA02  CN9 pin 1         analog / digital
1  A1   PB08  CN7 pin 5 (M1FB)  analog / digital
2  A2   PB09  CN7 pin 3 (M2FB)  analog / digital
3  A3   PA04  CN9 pin 3         analog / digital
4  A4   PA05  CN9 pin 5         analog / digital
5  A5   PB02  CN9 pin 7         analog / digital
6  D6   PA20  CN7 pin 6 (M2SF)  digital
7  D7   PA21  CN7 pin 4 (M1SF)  digital
```

`OPn,v` sets pin n as output, `IP2n` reads its digital level (outputs read back the real pin level), `ANn` reads pins 0-5 with the ADC. CN9 also carries SDA/SCL, with the 4k7 pull-ups R13/R14 on the board.

The PCA9540 I2C multiplexer and the encoder/temperature connectors (CN3, CN4, CN6) are marked DNP on the schematic, for compatibility with the original SatNOGS board only. The firmware does not use them.

## Tuning

* `HOMING_SPEED`: seek speed. When the end-stop triggers, the axis decelerates past it and comes back to the trigger point, so it overshoots by speed^2 / (2 * acceleration) steps: about 13 deg at the default 6400 steps/s and 3200 steps/s^2. Lower it if your mechanics have less margin past the switch.
* `HOME_DELAY`: time allowed for that return movement before a homing error.
* `MOTOR_CURRENT_MA`, `HOLD_MULTIPLIER`: driver current.

## Changes from the previous version

* Easycomm parser rewritten. The old one did not work with Hamlib >= 4.6: the separate `AZ` and `EL` queries were parsed as set commands with an empty value, which set the target to 0 deg.
* `VL` now decreases azimuth and `VR` increases it, as in Hamlib (they were swapped). Velocity commands are now executed: the old control loop ignored them.
* `GE` values changed to the Easycomm III mapping: no error is now 0 (was 1), and errors are true bitmasks.
* `CR`/`CW` registers 1-6 (PID gains) removed. `CR` replies now echo the command (`CR7,0.00` instead of `7,0.00`), as the specification requires.
* `SA SE`, `RESET` and `PARK` no longer send an unsolicited position reply.
* Lines split across loop iterations are no longer lost, and the receive buffer can no longer overflow.
* PID variables removed from `globals.h`.
* Pin map checked against the RotatorMobo rev 1.0a schematic: `M2FB` is A2 (was A0), the wrong `SDA_PIN 3`/`SCL_PIN 4` were removed (I2C is on PA22/PA23), and the old `PIN12`/`PIN13` are now the DIAG inputs.
* TMC2209 configured with `I_scale_analog = 0` (VREF is not connected on this board).
* Chopper mode chosen by the SPREAD jumpers with the standard polarity (GND = StealthChop). The old code wrote `en_spreadCycle = 1`, which inverted the jumpers: 3V3 gave StealthChop.
* AUX/AUX2 pins usable as GPIO with OP/IP/AN.
* End-stop pull resistor chosen so that a disconnected cable never reads as triggered.
